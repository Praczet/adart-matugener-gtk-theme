# ADArt-Unclaimed-Bloom

ADArt-Unclaimed-Bloom is a GTK theme source tree based on the old GTK Moonmix
user CSS override setup. Its palette is generated by
Unclaimed Bloom, which mixes a base palette (currently
`nord-tweak-dark`) with Matugen wallpaper colours.

GTK3 is the main target. GTK4 support exists for plain GTK4 apps such as
`pavucontrol`, but this is not a full libadwaita theme.

## Layout

```text
themes/
└── ADArt-Unclaimed-Bloom/
    ├── gtk-3.0/
    │   ├── gtk.css
    │   ├── gtk-dark.css
    │   ├── base/                           # vendored adw-gtk3 + bridge.css
    │   ├── gtk-adart-unclaimed-bloom.css   # palette (generated)
    │   ├── widgets/
    │   └── apps/
    │       ├── thunar.css
    │       ├── gimp.css
    │       └── yad.css
    └── gtk-4.0/
        ├── gtk.css
        ├── gtk-dark.css
        ├── base/                           # vendored adw-gtk3 + bridge.css
        ├── gtk-adart-unclaimed-bloom.css   # palette (generated)
        └── widgets.css

gimp/
└── ADArt-Unclaimed-Bloom/
    ├── gimp.css
    └── gimp-dark.css
```

`input/` and `docs/` are ignored by Git and kept only as local notes.

## Layers

Each `gtk.css` imports, in order:

1. `base/` – vendored [adw-gtk3](https://github.com/lassekongo83/adw-gtk3)
   v6.5 dark (LGPL-2.1, see `base/LICENSE-adw-gtk3`). It styles every GTK
   widget using libadwaita colour names.
2. `gtk-adart-unclaimed-bloom.css` – the palette, which redefines those names.
3. `base/bridge.css` – maps adw-gtk3 names the palette does not emit.
4. `widgets/` / `apps/` (GTK3) or `widgets.css` (GTK4) – the ADArt look.

Do not edit files under `base/` other than `bridge.css`; to update adw-gtk3,
replace them from a newer release.

## Palette

The palette lives in `gtk-adart-unclaimed-bloom.css` and is written by the
Unclaimed Bloom `gtk` target on every wallpaper change. Its plant hook copies
the rendered file to:

```text
~/.local/share/themes/ADArt-Unclaimed-Bloom/gtk-3.0/gtk-adart-unclaimed-bloom.css
~/.local/share/themes/ADArt-Unclaimed-Bloom/gtk-4.0/gtk-adart-unclaimed-bloom.css
~/.config/gtk-4.0/gtk.css
```

Do not hand-edit the palette file. Change colours in Unclaimed Bloom instead:

```text
~/.config/unclaimed-bloom/targets/gtk/recipes/<recipe>.json
~/.config/unclaimed-bloom/targets/gtk/templates/unclaimed-bloom.css
```

Regenerate without changing the wallpaper:

```sh
spore sow daily-gtk gtk && spore grow daily-gtk gtk && spore plant daily-gtk gtk
```

The copies in this repo are only a fallback for a fresh install.

## Install

Install the theme for the current user:

```sh
scripts/install-theme
```

It installs to:

```text
~/.local/share/themes/ADArt-Unclaimed-Bloom
~/.config/GIMP/3.2/themes/ADArt-Unclaimed-Bloom
```

An already planted palette in the installed theme is kept, so reinstalling
does not revert the wallpaper colours.

Set GTK to use:

```text
ADArt-Unclaimed-Bloom
```

For Hyprland, make sure no stale environment variable overrides it. In this
setup, `GTK_THEME` should be `ADArt-Unclaimed-Bloom` or unset.

## Development Loop

After CSS changes:

```sh
scripts/dev-install
```

That reinstalls the theme and quits Thunar so the next launch reloads CSS.

For GTK3 testing:

```sh
gtk3-demo
gtk3-widget-factory
thunar
```

For GTK4 testing:

```sh
pavucontrol
```

For GIMP, select the matching app theme inside GIMP:

```text
Edit > Preferences > Interface > Theme > ADArt-Unclaimed-Bloom
```

GIMP ships its own theme CSS and the default GIMP theme overrides normal GTK
theme colors. The bundled GIMP theme maps GIMP's own color variables back to
the installed ADArt-Unclaimed-Bloom palette.

Apps that read GTK colours only at startup (for example DBeaver/SWT) need a
restart to pick up a new palette.

## Scope

GTK3:

- normal theme entrypoints under `gtk-3.0/`
- widget CSS split under `gtk-3.0/widgets/`
- app fixes under `gtk-3.0/apps/` (Thunar, GIMP, YAD)
- GIMP app theme under `gimp/ADArt-Unclaimed-Bloom/`

GTK4:

- shared generated palette
- adw-gtk3 base plus plain GTK4 widget CSS
- useful for apps like `pavucontrol`
- not expected to fully style libadwaita apps

## Current Notes

Full widget coverage comes from the vendored adw-gtk3 base. The ADArt widget
layer only needs to cover what should look different from it, so the
generated palette, the base and the custom rules stay separate.
